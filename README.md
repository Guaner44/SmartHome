## 三、核心类设计说明

### 3.1 类一览

| 类 / 模块 | 职责（一句话） | 主要属性 | 主要成员函数 |
| --- | --- | --- | --- |
| `Device` | 表示**一台**设备这一实体，保存自己的属性、回答自己的状态，是唯一能修改开关状态的对象 | `id_` 编号、`name_` 名称、`room_` 所在房间、`on_` 开关状态（全部 private） | 构造函数；`id() / name() / room() / isOn() / statusText()`（const 只读查询）；`turnOn() / turnOff()`（行为）；`toString()`（完整信息文本） |
| `DeviceManager` | 管理**一组**设备：校验并创建设备、按编号查找、执行开关控制、列表显示；保证编号唯一 | `devices_`：`std::vector<Device>` | `addDevice()`、`setPower()`、`findById()`、`printAll()`、`size() / empty() / devices()`（const） |
| `Result`（枚举） | 把"操作是否成功、失败原因"表达成可判断的数据，替代返回字符串或打印提示 | — | 取值：`Ok / EmptyId / DuplicateId / EmptyName / NotFound` |
| `ConsoleInput`（工具命名空间） | 集中处理控制台输入：读一行、去首尾空白、判断菜单编号是否合法 | — | `trim()`、`readLine()`、`readMenuNumber()` |
| `main.cpp`（界面层） | 界面与流程：打印菜单、收集输入、调用类完成工作、把 `Result` 翻译成中文提示 | 局部 `DeviceManager manager` | `printMenu()`、`printDevice()`、`failureReason()`、`handleAddDevice() / handleListDevices() / handleShowDevice() / handleSwitch()` |

### 3.2 对象关系与调用关系

```text
main()  ──持有──>  DeviceManager manager
                     │  组合（containment）
                     ▼
                std::vector<Device> devices_   ──>  Device D01 / D02 / D03 ...
                     ▲
                     │ findById() 返回 Device*（找到）或 nullptr（找不到）
main() ──────────────┘   界面层只读取/调用，不直接改私有字段
```

- **包含关系**：`DeviceManager` 用 `vector<Device>` 组合多个 `Device` 对象，设备对象随管理器一起存在；`Device` 不反向持有管理器，不存在循环依赖。
- **职责边界**：`Device` 不知道"列表"和"输入输出"；`DeviceManager` 不知道"菜单"和"中文提示"；`main.cpp` 不含任何业务规则（编号是否重复、状态怎么变，都由类负责）。
- **数据流**（以"开关设备"为例）：
  `菜单 4` → `ConsoleInput::readLine()` 取编号 → `DeviceManager::setPower(id, true)` → 内部 `findById()` → `Device::turnOn()` 改私有状态 → 返回 `Result` → 界面层用 `statusText()` 显示最新状态。

### 3.3 为什么这样划分文件

| 决策 | 原因 |
| --- | --- |
| `Device` 与 `DeviceManager` 分开 | 一个是"实体"，一个是"集合的管理者"；后面的 Lab03 会把设备放进 `Room` 组合管理，需要 `Device` 能被复用 |
| 每个类一对 `.h / .cpp` | 声明与实现分离，`main.cpp` 只依赖头文件，便于增量开发时只改实现 |
| 单独抽出 `ConsoleInput` | 菜单输入校验逻辑（空输入、非数字、EOF）只写一次，Lab02 及以后继续复用 |
| 用 `Result` 枚举而不是在类里打印中文 | 类只返回结果，界面层负责提示文字，业务与界面解耦；也便于现场加测试 |
| 编号创建后不提供 setter | 编号是唯一标识，Lab02 明确要求"编号创建后保持不变"，现在就把它固定住 |

### 3.4 封装细节

- `Device` 的四个字段全部 `private`，外部只能通过 `turnOn() / turnOff()` 改变状态，无法把状态改成非法值。
- 查询函数全部声明为 `const`（`id() / name() / room() / isOn() / statusText() / toString()`，以及 `DeviceManager::printAll() / size() / empty() / devices()`），保证"查看"不会修改数据。
- 构造函数用初始化列表初始化全部成员，`on_` 固定为 `false`，因此"新建设备的开关状态为关闭"是构造出来的不变量，而不是靠调用方记得去关。

## 四、功能说明（对应任务要求逐条）

| 菜单 | 功能 | 输入 | 输出 | 对应要求 |
| --- | --- | --- | --- | --- |
| `1` | 添加设备 | 设备编号、名称、所在房间（房间直接回车 → 记为"未分配"） | 成功：显示该设备完整信息；失败：显示失败原因与当前设备总数 | 1(1)、3(1)、3(2) |
| `2` | 显示全部设备 | 无 | 表头 + 每行"编号 名称 所在房间 状态"，并显示设备总数；列表为空时提示"当前没有设备…" | 1(2) |
| `3` | 查看单个设备 | 设备编号 | 找到：完整信息；找不到：`查询失败：设备编号 D99 不存在。` | 1(1)、2(2) |
| `4` | 开启设备 | 设备编号 | `开启成功：D01 灯 当前状态：开启`；找不到则提示且不改动任何设备 | 2(1)、2(2) |
| `5` | 关闭设备 | 设备编号 | `关闭成功：D01 灯 当前状态：关闭`；同上 | 2(1)、2(2) |
| `0` | 退出 | 无 | `感谢使用，再见。` | — |
| 其他 | 非法菜单 | 例如 `9`、空行、`abc` | `菜单项 9 不存在，已返回主菜单。` / `输入无效：请输入菜单中列出的操作编号（0-5），本次操作已取消。` 然后回到主菜单 | T3 |

**数据校验规则（菜单 1）**

| 情况 | 提示 | 是否创建 |
| --- | --- | --- |
| 编号为空或全是空格 | `创建失败：设备编号不能为空。` | 否 |
| 编号与已有设备重复 | `创建失败：设备编号 D01 已存在，不能重复创建。` | 否 |
| 名称为空或全是空格 | `创建失败：设备名称不能为空。` | 否 |
| 正常输入 | `创建成功，设备信息如下：…` | 是，初始状态为"关闭" |
| 房间为空 | 记为"未分配" | 是 |

**健壮性**

- 菜单输入全部用 `std::getline` 读取，不用 `std::cin >>`，避免残留回车或输入失败后 `std::cin` 进入错误状态导致死循环。
- 输入结束（例如测试输入文件读完）时程序输出"输入结束，程序退出。"并正常结束，不会空转。
- 任何非法输入都只回到菜单，不退出程序、不改变已有数据。

## 六、C++ 知识点在代码中的落点（对应代码审查问题）

| 知识点 | 落点 | 解决了什么问题 |
| --- | --- | --- |
| **类的定义** | `include/Device.h`、`include/DeviceManager.h` | 把"一台设备"和"一组设备"各自的数据与操作封装成两个类型，而不是用一堆全局变量 + 平行数组 |
| **对象（创建与使用）** | `main.cpp` 中 `DeviceManager manager;`；`DeviceManager::addDevice` 中 `devices_.push_back(Device(id, name, room));`；`findById` 返回 `Device*` | 设备以对象形式存在，编号/名称/状态作为一个整体被创建、查找和修改，不会出现"编号数组和状态数组不同步" |
| **成员函数（行为）** | `Device::turnOn() / turnOff()` 改私有状态；`Device::toString()` 生成完整信息；`DeviceManager::addDevice()` 校验后创建；`setPower()` 完成"查找 + 控制" | 行为跟着数据走：外部不需要（也无法）直接改 `on_`，状态变化只能经过受控的成员函数 |
| **const 成员函数** | `Device::id()/name()/room()/isOn()/statusText()/toString()`，`DeviceManager::printAll()/size()/empty()/devices()` | 显示和查询不会意外修改对象，编译器帮忙检查 |
| **构造与初始化列表** | `Device::Device(...) : id_(id), name_(name), room_(room), on_(false)` | 新设备一定处于"关闭"，不存在未初始化的开关状态 |
| **访问控制（private）** | `Device` 的 4 个字段、`DeviceManager::devices_` | 编号不能被随意改、状态不能被随意置位，校验规则不会被绕过 |
| **引用与指针** | `findById` 返回 `Device*`（可能为空，必须先判断）；`printAll(std::ostream&)` 传引用避免拷贝 | 表达"可能找不到"的语义；显示时直接写向目标流 |
